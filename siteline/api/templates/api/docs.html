How to use the API

For whoever sets up the system that reads from Siteline. The same details are in the OpenAPI description, which tools such as Power BI and Postman can load.

Make a token

The basics

  • Address: {{ api_base }}, then the endpoint, e.g. {{ api_base }}rfis/.
  • Send the token in a header on every call: Authorization: Bearer slk_…. Tokens in the address are not accepted.
  • Read only: only GET works.
  • Lists come {{ page_size }} to a page (?page=2; up to {{ max_page_size }} with ?page_size=), with count, next and previous. Add ?updated_since=2026-11-01 where it's listed to fetch only what has changed.
  • Money is text with two decimal places ("1250.00"), excluding VAT unless the field says otherwise. Times are UTC.
  • Each token can make {{ limit }} calls every {{ window_minutes }} minutes. Every call is logged under Settings → API.
  • A token reads one company, as a member of staff would: every job that isn't archived. Ids from another company, or archived jobs, answer 404.
curl -H "Authorization: Bearer slk_…" "{{ api_base }}rfis/?project=12&status=OPEN"

When something goes wrong

Error answers
AnswerWhat it means
400A filter isn't right; the message says which and how.
401No token, or the token doesn't work (revoked, run out, or its maker is no longer an owner or admin).
402The workspace is locked until its subscription is paid.
403The token wasn't given that resource group.
404Not found, or not something this token can see.
429Too many calls: wait the number of seconds in Retry-After.
